# Jupasu AI 프로젝트 전략 가이드 (3주 완성 로드맵)

## 1. 프로젝트 개요
- **목표:** 취업용 포트폴리오를 위한 고성능 AI 에이전트 서버 구축
- **기간:** 3주 (토이 프로젝트)
- **핵심 기술 스택:** FastAPI, LangChain, LangGraph, vLLM, LangSmith

## 2. LLM 전략 (Qwen 3.5 & Hybrid)
- **메인 모델:** **Qwen 3.5 9B / 27B** (최신 오픈 소스 모델)
  - **이유:** Berkeley Function Calling Leaderboard(BFCL) 기준, 소형 모델 중 최정상급 툴 콜링 성능 보유.
- **운영 전략 (Hybrid):**
  - **개발용:** Google Gemini 2.0 (빠른 로직 검증)
  - **배포/기술 증명용:** 로컬 vLLM (OpenAI 호환 API 엔드포인트 구성)
- **양자화 가이드:**
  - 16GB VRAM 기준: **Qwen 3.5 27B (4-bit 양자화)** 추천 (지능 극대화)
  - 안정성 우선: **Qwen 3.5 9B (8-bit 양자화)** (속도 및 긴 문맥 처리 유리)
  - *주의:* 4-bit 미만의 과도한 양자화는 툴 콜링 정확도를 파괴하므로 지양.

## 3. 인프라 및 모니터링
- **서버:** FastAPI (8001 포트 사용, vLLM 8000 포트 점유 대비)
- **디버깅:** **LangSmith** 연동 완료
  - 모든 툴 호출, 프롬프트 실행 과정을 시각적으로 추적 및 모니터링 가능.
- **브라우저 제어:** Flatpak 기반 Google Chrome 설치 확인됨 (향후 멀티모달 에이전트 확장 가능성 확보)

## 4. 구현 로드맵
### [1주차] Core Workflow
- LangGraph를 활용한 기본 에이전트 루프 설계
- Gemini 엔드포인트를 통한 프롬프트 및 툴 정의 완료

### [2주차] 로컬 모델 최적화
- vLLM을 통한 Qwen 3.5 로컬 배포 및 툴 콜링 정밀도 테스트
- 로컬 LLM의 한계를 극복하는 Few-shot 프롬프트 적용

### [3주차] 완성도 및 폴리싱
- 에러 핸들링 및 재시도 로직(LangGraph) 강화
- 최종 성능 지표(토큰 소모량, 응답 속도 등) 문서화
